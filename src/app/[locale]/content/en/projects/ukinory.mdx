Ukinory is a web app that recommends movies from your Letterboxd history, and helps two people pick something to watch together. Import your data, get a taste profile, and swipe through recommendations that adapt as you rate. An LLM explains each pick using your own rating history.

Each stage is separate, so processed data can be reused and failures in external services stay contained.

## Features

- **Import & enrichment**: upload the Letterboxd ZIP or CSVs, match movies against TMDb and enrich them with Wikidata (description, runtime, language, directors, genres).
- **Taste profile & recommendations**: a semantic profile built from watched and rated movies, used to rank unseen candidates from a global TMDb catalog plus movies contributed by other users.
- **Adaptive hybrid ranking**: content similarity through embeddings combined with ratings and interactions; ratings and swipes keep adjusting future results.
- **Personalized explanations**: a short Gemini explanation per recommendation, grounded in the user's real rating history.
- **Swipe system**: skip or add to watchlist, recording actions so the same movie is not recommended again.
- **Taste comparison**: join a shared room through a short-lived, single-use invite link (guests included) and get a compatibility score, shared favorites, divergences, an AI-written summary of each person's taste and joint recommendations neither has watched.
- **Paired swipes**: both users swipe through the same joint recommendations, and the movies they both want to see become their matches.
- **Real-time rooms**: WebSockets keep both clients in sync as the friend joins and the comparison is generated, with polling as a fallback.
- **Exports**: a Letterboxd-compatible CSV of the watchlist, and a full JSON export of the account's data.
- **Privacy**: log out, delete the account with all its data, and automatic cleanup of abandoned guest sessions and inactive rooms.
- **Resilient integrations**: retries, backoff and a consistent error format for import errors, rate limits and transient failures.

## Technical challenges

- Converting a guest session into a permanent account while keeping every record tied to the same user.
- Matching Letterboxd movies to TMDb despite ambiguous titles, unmatched entries and release-year mismatches, with Wikidata supplying the descriptive metadata. Caching, batching, request pacing and retries keep rate limits under control.
- Generating embeddings from heterogeneous movie data and using vector search for profiles and candidate pools, then blending similarity with ratings and swipes so results don't depend only on the initial import. The catalog combines TMDb with other users' movies so new users get candidates from day one.
- Prompting the LLM with the user's actual rating history, so explanations are specific instead of a list of similar titles.
- Keeping a shared room consistent: a lifecycle (invite, waiting, generation, abandonment) that holds under concurrent actions, an LLM call that must not run twice, and a clear decision on what each person can see of the other.
- Returning one error format across the API, whether the failure is internal or from an external service, and keeping the two exports separate (complete JSON vs. Letterboxd-ready CSV).

## Takeaways

- The hard part was the data pipeline (import, identifier resolution, enrichment, storage, embeddings, recommendation), not producing a single recommendation.
- Comparing movie embeddings captures taste better than matching genres or isolated attributes.
- Imported history is only the starting point; in-app ratings and swipes keep the system relevant.
- Designing for two users changes how you build: shared state, work that must run once, and privacy boundaries.
- Working with TMDb, Wikidata and Gemini gave me practical experience with caching, rate limiting, retries, batching and failure handling.
- With third-party APIs, an LLM and two users acting at once, tests are what let me change the pipeline without breaking it.
